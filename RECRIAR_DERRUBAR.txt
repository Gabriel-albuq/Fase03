1.6 ArgoCD
--------------------------------------------------------------------------
  kubectl create namespace argocd
  kubectl apply -n argocd --server-side --force-conflicts -f https://raw.githubusercontent.com/argoproj/argo-cd/<VERSAO>/manifests/install.yaml
  kubectl wait --for=condition=Ready pods --all -n argocd --timeout=300s

  <VERSAO>: tag fixa (vX.Y.Z), não "stable". Versão usada: ____________
  Substituir o <VERSAO> inteiro pela tag (ex.: v3.5.5); no bash o "<" é
  redirecionamento e dá "VERSAO: No such file or directory".
  --server-side evita o erro "annotations too long" no CRD de ApplicationSet.

1.7 Imagens no ECR (o destroy apaga as imagens: force_delete = true)
--------------------------------------------------------------------------
  Os workflows não têm workflow_dispatch. Para recriar a imagem com a
  MESMA tag que está no overlay:
    GitHub > Actions > <serviço> CI > run do commit da tag atual
    > "Re-run all jobs"
  A tag é v1.0.0-<sha7> do commit, então o re-run gera a mesma tag.

  A tag atual de cada serviço é a do newTag no overlay (o job update-gitops
  do CI muda a cada push), então ver no próprio arquivo:
    grep -r newTag gitops-repo/applications/*/overlays/production/kustomization.yaml

  Conferir:
    aws ecr list-images --repository-name auth-service --region us-east-1

2.2 Remover o que cria recursos AWS fora do Terraform
--------------------------------------------------------------------------
  Services do tipo LoadBalancer (ex.: ingress-nginx) criam ELBs e ENIs
  que o Terraform não conhece e travam o destroy da VPC.
  Conferir:
    kubectl get svc -A | grep LoadBalancer
  Se aparecer algo, apagar antes (ex.: helm uninstall ingress-nginx -n ingress-nginx)
  e esperar o ELB sumir no console (EC2 > Load Balancers).

  Hoje os Services são ClusterIP, então normalmente não há nada aqui.

--------------------------------------------------------------------------
2.3 Apagar as Applications do ArgoCD (opcional, mas deixa limpo)
--------------------------------------------------------------------------
  kubectl delete applications --all -n argocd
  (o finalizer resources-finalizer apaga os recursos de cada app)

--------------------------------------------------------------------------
2.4 Terraform destroy
--------------------------------------------------------------------------
  cd terraform/environments/prod
  terraform plan -destroy -out tfplan       # revisar: tudo "destroy"
  terraform apply tfplan
  rm tfplan
  cd ../../..

  Se falhar por dependência da VPC (subnet/ENI/security group em uso):
  quase sempre é um ELB que sobrou (ver 2.2). Apagar no console e
  rodar o destroy de novo.

--------------------------------------------------------------------------
2.5 Conferir que não sobrou nada cobrando
--------------------------------------------------------------------------
  aws eks list-clusters --region us-east-1
  aws rds describe-db-instances --region us-east-1 --query "DBInstances[].DBInstanceIdentifier"
  aws elasticache describe-cache-clusters --region us-east-1 --query "CacheClusters[].CacheClusterId"
  aws ec2 describe-nat-gateways --region us-east-1 --filter Name=state,Values=available --query "NatGateways[].NatGatewayId"
  aws elbv2 describe-load-balancers --region us-east-1 --query "LoadBalancers[].LoadBalancerName"
  # Tudo deve voltar vazio ([])

  Opcional: remover o contexto antigo do kubeconfig
